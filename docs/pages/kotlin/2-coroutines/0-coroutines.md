# 协程 (Coroutine)

## 概念

协程（Coroutine）是一个轻量级的并发编程解决方案，一般用来处理异步任务，它本质上是运行在用户态的轻量级任务执行单元。协程不是 Kotlin 特有的概念，如果抛开语言来讲，协程就是一个可以被暂停和恢复的函数。

协程处理异步通过挂起/恢复来实现，任务一直运行在用户态，和线程的阻塞不同，线程的切换会涉及用户态和内核态的切换，因此协程更轻量。而挂起/恢复的机制可以让我们以同步的代码结构来执行异步的任务，避免异步编码的层层回调，这也是协程的核心价值。

协程的运行必须依赖于线程，但是它又不绑定特定的线程，可以在不同线程之间灵活切换，一个线程内可以运行很多协程。

## 协程和线程的差异

核心差异有 3 个：

- **资源占用**：线程是操作系统任务调度的最小单元，创建一个线程就会分配很多资源（Java 一个线程大约占 1MB）；协程是 JVM 堆中普通的对象，占用的内存非常少。
- **挂起 vs 阻塞**：协程通过挂起/恢复来实现异步操作，遇到耗时操作时，会释放线程的控制权，让线程去执行别的任务；而线程的等待是阻塞式的，遇到耗时操作会一直占着 CPU 的资源不释放。
- **调度方式（抢占式 vs 协作式）**：线程的切换是操作系统的内核控制的，会涉及到内核态和用户态的切换，只有当线程抢到 CPU 的使用权线程内的任务才回执行；协程的切换是由代码主动触发(协作式)的，协程只存在于用户态中。

协程更适合于 IO 密集型任务，线程更适合于 CPU 密集型任务。

## 挂起/恢复的原理

Kotlin 协程的挂起和恢复，是通过编译期的 CPS 转换（Continuation-Passing Style）和状态机（State Machine）机制来实现的。
